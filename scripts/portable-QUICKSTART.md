# BridgeHub 快速上手（便携版）

解压后 **双击 `start.bat`**，浏览器会自动打开 http://localhost:4501。无需安装 Go、Bun 或 Node —— `runtime\bun\` 里已经带了一份，主站用它来跑插件。

> **解压提示**：请用 **7-Zip 或资源管理器右键解压**。PowerShell 的 `Expand-Archive` 对上百 MB 的包会静默少解压，导致启动文件缺失。

## 第一次使用

1. **创建管理员账号**：首次打开页面进入初始化向导，自己设定管理员用户名和密码（只存本机）。
2. **登录**：用刚建的账号登录控制台。
3. **创建 API 密钥**：「API 密钥」页点「创建 API 密钥」，复制 `sk-` 开头的密钥。该页顶部有完整连接教程。
4. **接入客户端**：客户端 Base URL 填 `http://localhost:4501/v1`，填入刚复制的密钥。

## 接入上游服务（重要）

本站不自带任何厂商的账号。要拿到模型，走**插件**这条路：

```
「插件」页 → 从市场安装一个 provider 插件 → 「服务」页登录你的账号
          → 点「注册渠道」→ 模型出现在 /v1/models
```

| 页面 | 干什么 |
| --- | --- |
| **插件** | 装了哪些包、市场里有什么、哪个有新版本 |
| **服务** | 每个订阅：账号、剩余额度、签到、插件自己的开关 |
| **路由** | 每个模型由谁提供服务、按什么顺序尝试 |

模型名有两套写法，都能用：

- `workbuddy-glm-5.3` —— 只走 WorkBuddy 这一家
- `glm-5.3` —— 裸名，按优先级在**所有**提供该模型的厂商之间故障转移

> 裸名的故障转移需要「系统设置 → 请求策略 → 重试次数」大于 0。默认是 2，设为 0 就只试第一家。

**没有账号也能先跑起来**：安装插件后即使不登录，渠道也会出现在列表里，只是请求会失败——这是预期行为，登录后自动恢复。

## 日常使用

- **启动**：双击 `start.bat`
- **停止**：关掉那个黑窗口（或 Ctrl+C）
- **数据位置**：全部在解压目录内 ——
  - `new-api-main\one-api.db`：账号、渠道、密钥、配置、用量
  - `new-api-main\data\plugin-host\`：插件本体、**登录凭证**、模型目录缓存
  - `runtime\bun\`：便携 Bun
  **备份就备份整个目录**，删除目录即彻底清理。
- **端口**：主站 4501

## 常见问题

**Q：双击 start.bat 闪一下就没？**
看是不是已经在运行（任务管理器里有 `new-api-dev.exe`）。这次窗口会停住并显示原因，读那条错误即可。

**Q：插件装上了，但模型列表是空的？**
还没登录。去「服务」页点该服务，用**你自己的**账号登录，然后回「插件」页点「注册渠道」。

**Q：某个账号显示「需要重新登录」？**
厂商把 refresh token 作废了，只能重新登录。服务页里那个账号会标红并给出原因。

**Q：端口被占用？**
改 `new-api-main\.env` 里的 `PORT`。

**Q：控制台日志是乱码？**
用 `start.bat` 启动（它会把控制台切到 UTF-8）。直接跑 exe 会因 Windows 默认 GBK 代码页而乱码。

**Q：能不能不用自带的 Bun？**
可以。设环境变量 `MAGPIE_BUN` 指向任何 Bun ≥ 1.4.2 的 `bun.exe`。

## 合规提醒

各插件依赖第三方平台的账号与接口，请自行确认使用方式符合对应平台的服务条款。本包仅供个人学习与自用。
